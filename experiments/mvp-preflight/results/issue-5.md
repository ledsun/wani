# #5: 独自 JavaScript なしの起動

## 現在の結論

[ruby/ruby.wasm#672](https://github.com/ruby/ruby.wasm/pull/672) の
`dc6b0ffd5800ed9bfc49268ed8021d456f10ddf8` からビルドしたローダーを一時同梱する方式を採用した。
公式 npm リリースではない。ローダー自体はビルド後に変更せず、HTML で取得先を指定する。

```html
<script src="runtime.pr672.js" data-ruby-wasm-url="./preflight.wasm"></script>
```

この方式で Ruby の起動・Markdown の取得・解析・描画を実行する。
Wani 独自の起動 JS と URL の文字列置換は不要。

## 検証

- 固定コミットのソースアーカイブと、ビルド成果物の SHA-256 を `provenance.json` に記録。
  独立した再ビルド手順でも同じローダーのチェックサムを再現した。
- 公開ディレクトリへコピーしたローダーが、同梱済みビルド成果物とバイト単位で同じことを検査。
- HTML の属性で指定した wasm を取得し、通信が同一 origin 内だけであることを確認する。
- 属性を別のパスへ変更しても起動できること、指定した wasm の取得失敗で CDN にフォールバックしないことを確認する。
- 空の属性は wasm 取得前に拒否される。属性省略時は従来の CDN への実リクエストを発行する。
  CDN 取得テストでは通信を遮断し、オンラインでの起動成功を主張しない。
- Ruby から取得する Markdown の404を通知する。

## 再現と公式版への移行

`npm run build:loader` で、固定コミット内のロックファイルと既存 npm スクリプトから再ビルドする。
LICENSE / NOTICE と再ビルド手順は `third_party/ruby-wasm-loader/` に保持する。
通常の wasm ビルドでは上流ソースの取得・ビルドは不要。

機能を含む公式 npm リリースが公開されたら、バージョンを固定し、ローダーのコピー元を切り替える。
HTML の属性は維持し、ブラウザーで回帰テストを実行する。

## 経緯

初回は公開版2.10.1の取得先が CDN に固定されていたため、URL1箇所を置換して検証した。
この置換を許容するかという判断は、ユーザーの指示により「PR の固定コミットをビルドして利用」で解決した。
マージ・公式リリース済みとしては扱わない。
