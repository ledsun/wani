# #6: 自動レイアウトと印刷

## 結論

Ruby から DOM を計測し、文字サイズを二分探索して調整できた。
画像・フォント待機後にレイアウトを確定し、Ruby が生成する印刷 DOM から PDF を出力できた。

## 検証

- 論理サイズ1920×1080のタイトル・本文・フッター領域。画面サイズ変更時は全体を縮尺変更。
- 本文16〜160px、タイトル24〜180pxの範囲で探索。画像待機を遅延レスポンスでも検証。
- SVG の縦横比、タイトルなし・画像だけの複数画像、長い非改行文字列での最小サイズと警告を確認。
- 画像ロード失敗は画像パスを、はみ出しはスライド番号と本文冒頭を表示。
- 通常版2ページ、ノート付き4ページ（スライド1→ノート1→スライド2→ノート2）を実際に生成。
- PDF.js は生成後の検査だけに使用。各用紙は320×180mm指定から1 PDFポイント未満の誤差であることを確認。
  Chromium は用紙寸法を丸めるため、16:9 の数学的な完全一致は要求しない。
- PDF の本文・画像内テキスト・フッター・仮の装飾文字と、ノートの除外／順番を検査。
  生成した最初の PDF ページをラスタライズし、画面スクリーンショットとともに目視確認した。

## 得られた知見

Ruby のイベント処理から同じ VM の evalAsync を再呼び出さず、Fiber で await 可能な処理を開始する。
画面用 transform をそのまま印刷に使うと画像付きページのフッター欠落を検出した。
印刷用は `zoom` でレイアウト寸法も縮める方式に変更すると欠落が解消した。

## 未検証・範囲外

OS の印刷ダイアログ操作、Edge / Firefox / Safari、Windows・WSL2、実際の日本語フォント群の差異。
画像の領域配分は仮の上限値を使っており、最適な画像配置は #1 で実装する。
装飾文字は検証用。#1 で要求される差し替え可能な SVG のデザインは未実装。
