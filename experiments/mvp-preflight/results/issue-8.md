# #8: 安全な共通パーサー

## 結論

YAML / Psych と kramdown + GFM を同じソースで使い、CRuby と ruby.wasm の両方で解析できた。
任意の HTML を直接挿入せず、許可した AST 要素・属性から生成する方式を検証した。

## 検証

各正常入力は実際の CRuby CLI の JSON とブラウザーのモデル全体を比較し、固定の期待値も検査。
異常入力は両環境で同じエラー分類を確認する。合計10ケース。

- Front Matter・フッター・タイトル・ノート・画像パス・追加見出しの警告。
- バッククォート／チルダのコードフェンスとインデントコード内の区切り、ノート記法を本文として保持。
- ノート内の区切りはスライド分割に使わない。ノートの書式は別途安全にレンダリングする。
- XML/HTML の生要素は落とし、HTML 属性をそのまま引き継がない。
- javascript / data スキーム、HTML entity で隠したスキームを許可しない。
- YAML.safe_load の permitted_classes / permitted_symbols は空、aliases は false。
  オブジェクトタグ・alias・構文エラー・不正な footer 型・閉じていない Front Matter を拒否。
- 閉じていないノートを拒否。検証中に漏れを見つけ、共通ソースを修正して wasm を再生成した。

## #1 への提案と範囲

core は Hash / Array / String のモデルを返し、kramdown の AST を外へ公開しない。
ファイルの存在確認は CRuby の validator 側、DOM 操作は browser 側へ分離する。

このレンダラーは必要な代表要素だけを扱う検証用実装で、完全な Markdown 対応・汎用サニタイザーではない。
複雑なリスト／引用とフェンスの組み合わせ、全ての壊れた構文、画像ファイルの存在確認、
HTTP サーバーのパストラバーサル対策は #1 側の実装とテストが必要。
