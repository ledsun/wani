# #1 MVP 実装記録

## 実装した機能

- Ruby gem / `wani new` / `wani check` / `wani serve`。サンプル生成・上書き防止・オプション・正常終了。
- 選択した Markdown と画像、gem のアセットを分離した静的配信。パストラバーサル・不正エンコード・シンボリックリンク逸脱を拒否。
- 両実行環境で共有する kramdown / GFM パーサーと独自モデル。Front Matter・タイトル・本文・ノート・フッター・画像パス・診断。
- 安全な YAML 解析、AST から許可した要素だけを生成するレンダラー。任意の HTML / 属性・危険な URL を引き継がない。
- Ruby による DOM 構築、全キーボード操作、URLハッシュの読み書き、全画面表示。
- 1920×1080 / 16:9 の論理スライド、画面への縮尺変更、DOM計測による文字サイズ探索、画像待機・縦配置、はみ出し警告。
- 控えめな差し替え可能 SVG のウサギ・鮫の装飾。Front Matter で無効化も可能。
- 別ウィンドウの発表者画面。現在の本文・ノート・ページ番号を postMessage で同期。
- Ruby が生成する通常PDF / ノート付きPDF の印刷DOM。画像・フォントを待ち、印刷用 CSS で1スライド1ページに配置。

## 依存と wasm

実行時 gem は kramdown 2.5.2、kramdown-parser-gfm 1.1.0、rexml 3.4.4、WEBrick 1.9.2。
ビルドに ruby_wasm 2.10.1 と `@ruby/4.0-wasm-wasi@2.10.1` を使用。
`rbwasm pack` で標準ライブラリ入り wasm に core / browser / Pure Ruby gem を追加する。
CLI / WEBrick / 開発ツールは wasm に含めない。

ローダーは PR #672 のコミット `dc6b0ffd5800ed9bfc49268ed8021d456f10ddf8` のビルドを変更せず同梱する。
未リリース版として出所・SHA-256・ライセンス・再ビルド手順を記録した。
HTML の属性で取得先を指定し、独自アプリ JavaScript は作成していない。

生成 wasm: 33,245,347 bytes、2026-10-25 23:05:18 JST。
ソース・wasm・ローダーのハッシュをブラウザーテストで照合し、古い生成物の混入を検出する。
生成物はソース管理対象外だが、ビルドした gem に含まれる。

## 自動検証

- Ruby: `bundle exec rake test`。12件・78アサーション、失敗なし。
- ブラウザー: `CHROMIUM_PATH=/usr/bin/google-chrome npm test`。10件成功、22.4秒。
  操作・各画像形式・レイアウト・全画面・ノート同期・解析結果のCRubyとの一致を確認。
- 実PDF: 通常3ページ、ノート付き6ページ。各用紙が320×180mm指定から1 PDFポイント未満の誤差であること、
  本文・画像内テキスト・フッター・ノートの除外／順番を検査。印刷DOMの装飾画像も確認。
- gem: `scripts/smoke_package.rb` で一時環境にローカルインストール。
  ソースツリーを参照していないこと、インストール済みwasmの一致、`new → check → serve`・HTTP配信・SIGINT正常終了を確認。
- 負の検証: HTML の wasm パスを一時的に壊すと起動テストが非ゼロ終了。復元後に起動を再確認。
- スクリーンショットを目視確認し、タイトル・本文・画像・フッター・装飾を確認した。

## 環境と未検証範囲

OS の印刷ダイアログ操作はこの環境で未検証。README に手順を記載した。

## 既知の制約・今後の改善

全 Markdown 拡張の網羅、構文ハイライト、最適な画像の自動配置、ライブリロードは対象外。
複雑に入れ子になったリスト・引用とコードフェンスの全方言は網羅していない。
発表者画面はメインの VM に依存するので、メイン再読み込み後は開き直す。
公式ローダーのリリース後の移行、追加ブラウザーでの確認、画像配置の改善を今後の候補とする。
